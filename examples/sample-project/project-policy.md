# Fictional sample policy

This directory is a teaching example. Names, sessions, repository URLs, events, and commits are invented. It grants no permission for real actions.

The sample human authorized three bounded sessions and coordinator/owner milestone messages. Owners use separate workspaces. The coordinator maintains this registry; implementation, Git integration, review, and checks remain with the owners.

P02 may implement reads after the P01 contract is accepted. P03 may prepare a rendered preview using that contract while actual P02 integration and publication wait. The sample human approves shown UI before application implementation. Writing tests is allowed in this fictional project; owners run relevant tests and checks. This policy illustrates that a test restriction from another project does not transfer here.

Publication requires a completed scope and human approval; merge requires the particular reviewed PR's approval. Deployment, paid infrastructure, credentials, force-push, and stacked PRs are unapproved. Acceptance is a separate recorded decision. A verified merged session is retired from monitoring and reminders immediately, without implied cleanup or deletion authority.

The sample coordinator monitors only active P02/P03 incrementally and stops when all three phases are delivered and accepted. Actual background automation is not included in this example.
